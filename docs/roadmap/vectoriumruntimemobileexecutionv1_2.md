⭐ 0. Executive Summary

Vectorium Runtime v1.2 formalizes the transition from prototype spectral‑expressive engine to mobile‑ready proof‑of‑concept. This roadmap outlines three parallel execution paths, each targeting a different altitude of thermodynamic stability, expressive fidelity, and distribution feasibility:

1. Python → Mobile Runtime (BeeWare / Kivy)  
2. Unity/Godot Plugin (C++/Rust Spectral Core)  
3. Rust Core + Mobile Bindings (Research‑Grade Thermodynamic Alignment)  

Each path includes:

- dependencies  
- required subsystems  
- missing components  
- risks  
- expected outcomes  

The roadmap integrates the Shared‑Horizon haptic math, semantic haptic primitives, and NDH‑safe tactile envelopes, ensuring ethical and thermodynamic alignment.

⭐ 1. Path A — Python → Mobile Runtime (BeeWare / Kivy)

Fastest path • Best for prototyping • Weakest thermodynamic alignment

---

1.1 Purpose

Create a rapid, functional mobile demo of the expressive engine using Python‑native tools.

1.2 Dependencies

- BeeWare / Kivy mobile runtime  
- Python 3.10+  
- NumPy (mobile‑safe build)  
- Lightweight UI layer  
- Local IPC (TCP/WebSocket)  
- Shared‑Horizon haptic translation tables (simplified)  

1.3 Required Subsystems

- 9D Laplacian engine  
- drift clamps  
- safety membrane  
- expressive → glyph projection  
- expressive → haptic mapping  
- mobile frame pacing (30–60 Hz)  
- mobile IPC loop  

1.4 Missing Components

- full bisimulation checker  
- device‑specific haptic envelopes  
- NDH‑safe tactile primitives  
- spectral logging compression  

1.5 Risks

- Python runtime overhead  
- thermal throttling  
- inconsistent haptic support  
- limited distribution channels  

1.6 Expected Outcome

A working mobile demo proving:

- expressive geometry  
- spectral operators  
- safety membrane  
- tactile mapping  
- glyph projection  

This is the fastest path to a playable proof‑of‑concept.

⭐ 2. Path B — Unity/Godot Plugin (C++/Rust Spectral Core)

Most polished • Best UI/haptics • Ideal for public demonstration

---

2.1 Purpose

Integrate the spectral core into a professional mobile engine with full UI, haptics, and rendering support.

2.2 Dependencies

- Unity or Godot  
- C++ or Rust spectral core  
- GDNative or Unity Native Plugin  
- CoreHaptics (iOS)  
- Android Vibrator API  
- Shared‑Horizon semantic haptic primitives  
- device‑class envelopes  

2.3 Required Subsystems

- spectral core compiled to native  
- expressive → glyph atlas  
- expressive → fog density  
- expressive → haptic primitives  
- NDH‑safe tactile envelopes  
- bisimulation checker  
- safety membrane → UI/haptics integration  
- mobile frame pacing  

2.4 Missing Components

- operator‑safe tactile mapping  
- reversible tactile operators  
- spectral logging layer (mobile mode)  

2.5 Risks

- plugin complexity  
- cross‑platform haptic differences  
- native memory management  

2.6 Expected Outcome

A polished mobile application demonstrating:

- expressive geometry  
- spectral stability  
- tactile semantics  
- fog/environment mapping  
- glyph atlas projection  

This is the best path for public demonstration.
